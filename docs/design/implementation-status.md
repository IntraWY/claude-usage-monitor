# Desktop implementation status

## Implemented

- Electron Windows application in `desktop-app`, kept separate from the existing extension and PWA.
- Compact/Detail, multiple profile cards, used/remaining toggle, configurable minute refresh, manual refresh, persisted per-quota notification preferences, native always-on-top, close-to-exit.
- Codex CLI app-server: initialize, account/read, account/rateLimits/read, paginated model/list and account/login/start. Separate app-owned profiles for additional accounts; default CLI account detected. Merge only when a provider account ID is returned.
- Claude app-owned web-session login and organization usage connector based on the checkout's original endpoint; unknown quota keys preserved verbatim. HTTP 429 retry-after is honoured.
- Sandboxed, isolated renderer with a narrow preload bridge; remote login pages have no Node/preload access. Secrets are not sent to the renderer or stored in preference JSON.
- Portable Windows x64 packaging; NSIS command retained for builds on Windows. Distribution is unsigned with placeholder artwork.

## Evidence

- Official Codex repository documentation: https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md
- Schemas generated by installed codex-cli 0.159.0-alpha.3 establish the exact request/response contracts used by the connector.
- Real initialization/account-read check against an isolated empty CODEX_HOME passed, including concurrent startup and clean shutdown; no personal credentials used.
- Four domain tests passed: multi-bucket normalization, unknown/invalid Claude data, notification deduplication/reset confirmation and settings validation.
- Chromium renderer checks passed for mode switches, percent conversion, per-quota preference retention, escaped model labels, pin/close IPC dispatch and unreadable state. Native Windows pinning/toasts were not exercised by these tests.
- Windows runtime executable identified as PE32+ x86-64. Packaged ASAR runtime contents compared byte-for-byte with all seven source runtime files.

## Outstanding (do not claim complete)

- Windows end-to-end Sign in/live quota validation with actual user accounts.
- Claude account email, complete model catalog, Fable source field, reliable provider-issued user identity and detection of externally signed-in Chrome/Claude CLI profiles. Organization IDs must not be treated as user identities.
- Official logo/mascot assets and Windows credential-storage review.
- Native Windows notification delivery/always-on-top/shutdown validation and distribution signing.
- NSIS installer cross-build failed because Wine is absent; generated incomplete installer was removed. Portable ZIP is the intended artifact instead.
